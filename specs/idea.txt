Anonymous Messages vs. Schema ConstraintsSpec Conflict: RFC 003 (Security Envelope) vs. RFC 004 (SDK Storage & Types).The Gap: RFC 003 uses Rate-Limiting Nullifiers (RLN) so users can post anonymously to group channels without revealing their did:key. However, RFC 004 defines the SQLite messages table with author_did TEXT NOT NULL and the TypeScript ChatMessage interface with authorDid: string.Impact: In anonymous group channels, forcing a non-nullable author_did breaks identity-hiding or forces developers to substitute dummy values, corrupting the database model.Fix Required in RFC 004:Update SQLite schema: Change author_did TEXT NOT NULL to author_did TEXT NULL.Update TypeScript interface: Make authorDid?: string optional and add nullifierHash?: string for anonymous tier channels.TypeScriptexport interface ChatMessage {
  id: string;
  channelId: string;
  authorDid?: string;         // Null in anonymous RLN channels
  nullifierHash?: string;     // Present in anonymous RLN channels
  content: string;
  timestamp: number;
  verifiedTier: number;
}
2. Missing Proof & Nullifier Persistence in Message SchemaSpec Conflict: RFC 003 (Groth16 Verification) vs. RFC 004 (Local Database Schema).The Gap: When a peer receives an incoming message over QUIC (RFC 001), it must verify the ZK range proof or RLN nullifier signature (RFC 003). RFC 004's messages table stores content_ciphertext, epoch, and verified_status, but provides no column for zk_proof or nullifier_hash.Impact: If an incoming message is stored locally and re-evaluated later (e.g., during a background database re-index or peer dispute), the SDK cannot re-verify the Groth16 proof without re-fetching it over the network.Fix Required in RFC 004: Add zk_proof BLOB and nullifier_hash BLOB to the messages table schema in Section 4.2.3. Serialization Bridge: Raw Bytes vs. BN254 Field ElementsSpec Conflict: RFC 004 (Storage Engine) vs. RFC 003 (Circom / SnarkJS Circuit Inputs).The Gap: RFC 004 stores keys as raw byte arrays (BLOB / Uint8Array), such as rln_identity_secret BLOB. SnarkJS WASM workers (RFC 004 Section 6) require circuit inputs formatted as stringified BigInt scalar field elements within the BN254 prime field $\mathbb{F}_p$.Impact: Passing raw Uint8Array byte buffers directly into zk-prover.worker.ts will trigger SnarkJS serialization crashes at runtime.Fix Required in RFC 004: Define an explicit SDK serialization utility in the SnarkJS Worker section to convert byte buffers into field string representations before posting messages to zk-prover.worker.ts:TypeScript// Buffer to BN254 Scalar Field Conversion
const circuitInputs = {
  identitySecret: bytesToBigInt(rlnIdentitySecret).toString(),
  userScore: BigInt(profile.subjectiveScore).toString(),
};
4. QUIC Substream Multiplexing AlignmentSpec Conflict: RFC 001 (Iroh/QUIC Transport) vs. RFC 002 (Automerge Sync) & RFC 004 (Vouchers).The Gap: RFC 001 specifies QUIC binary frame headers. RFC 002 sends Automerge CRDT binary state vectors (automerge_doc_state), while RFC 004 Section 5.2 streams blind vouchers ($B = \text{Blind}(r)$). RFC 001 needs to explicitly allocate stream protocol identifiers so receiver workers can route incoming streams without reading full message payloads.Fix Required in RFC 001 & RFC 004: Standardize StreamType header IDs across all spec files:0x01: CRDT_AUTOMERGE_SYNC (RFC 002)0x02: E2EE_DIRECT_MESSAGE (RFC 003/004)0x03: WOT_BLIND_VOUCHER_EXCHANGE (RFC 004)0x04: RLN_SIGNAL_BROADCAST (RFC 003)5. Network Epoch Clock SynchronizationSpec Conflict: RFC 003 (RLN Epoch Windows) vs. RFC 004 (messages.epoch).The Gap: RFC 003 uses epoch-based rate-limiting to prevent spam. RFC 004 writes epoch INTEGER NOT NULL into local SQLite tables. However, if Peer A's system clock is ahead by 15 seconds, its generated Groth16 proof will use epoch $E_{A}$, while Peer B verifies against epoch $E_{B}$, causing valid messages to be dropped as invalid proofs.Fix Required in RFC 004: Explicitly define the epoch duration formula in Section 5/6 and tie it to the Iroh P2P network clock drift offset calculated during DicsussionClient.init():$$\text{Epoch } E = \left\lfloor \frac{T_{\text{local}} + \Delta_{\text{network}}}{10\text{s}} \right\rfloor$$Patching these 5 points across the spec files will align the data structures end-to-end—from the QUIC wire protocol up to the React Context bindings.
